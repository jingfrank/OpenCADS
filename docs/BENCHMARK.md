# 异常检测系统性能测试报告

## 1. 测试概览
本周我们对异常检测系统在不同计算平台下的推理性能进行了基准测试。测试涵盖了纯CPU环境以及搭载 Tesla T4 和 Tesla V100 GPU 的加速环境。主要关注指标为单张图像的**模型推理耗时 (Inference Time)** 和**端到端总处理耗时 (Total Time)**。

## 2. 性能对比数据
下表展示了不同平台处理单张图像的平均耗时（单位：毫秒）：

| 硬件平台 | 推理耗时 (ms) | 总处理耗时 (ms) | 相对 CPU 加速比 (推理) |
| :--- | :---: | :---: | :---: |
| **CPU** | 801.53 | 857.28 | 1.0x (基准) |
| **Tesla T4** | 151.7 | 241.07 | 5.3x |
| **Tesla V100** | 29.71 | 157.38 | 27.0x |

> **注**：总处理耗时包含：数据预处理、模型推理、后处理（热图生成与叠加）等全流程时间。

## 3. 分析与结论

1.  **GPU 加速效果显著**：
    *   相比 CPU，**Tesla T4** 提供了约 **5.3倍** 的推理性能提升。
    *   **Tesla V100** 性能最为强劲，推理速度约为 CPU 的 **27倍**，是 T4 的 **5倍** 以上。

2.  **实时性评估**：
    *   **V100 平台**（总耗时 ~0.16秒）完全满足高速产线的实时检测需求。
    *   **T4 平台**（总耗时 ~0.24秒）性能表现均衡，适合大多数常规检测场景，且更具性价比。
    *   **CPU 平台**（总耗时 ~0.86秒）虽然较慢，但对于 1秒/张 以内的低速检测场景仍然可用，可作为低成本或应急部署方案。

3.  **瓶颈分析**：
    *   随着计算能力的提升（从 CPU 到 V100），推理时间大幅压缩，非推理部分（如数据传输、预处理）在总耗时中的占比逐渐上升。例如在 V100 上，推理仅占总耗时的约 19%，说明后续优化重点可转向数据流水线和后处理逻辑。

## 4. 后续建议
*   **生产环境推荐**：首选 **Tesla T4**，在保证足够实时性（<300ms）的前提下，成本优于 V100。
*   **低资源环境**：已验证 CPU 版本可行性，可用于无 GPU 的边缘工控机部署，无需改动代码即可平滑迁移。
